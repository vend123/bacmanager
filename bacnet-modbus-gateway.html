// the problem

Mixed sites need a bridge somewhere

The AHU and the BMS speak BACnet. The energy meters, VFDs and older equipment speak Modbus. Somewhere between them, something has to translate — and that job usually means an off-the-shelf protocol-converter box: one specific SKU for BACnet/IP-Slave-to-Modbus-Master, a different SKU for the reverse direction, another for MS/TP instead of IP. BACManager replaces that whole shelf of boxes with one PC already running the tool your team uses for commissioning anyway.

// questions

Gateway — FAQ

Does this replace a hardware BACnet-Modbus gateway box?+
For most sites, yes. A PC (or a small always-on Windows box) running BACManager does the same job a dedicated protocol converter appliance does — no separate hardware to buy, wire and maintain, as long as the PC stays powered on.
Does the Gateway run without keeping the window open?+
Yes. It can minimize to the system tray and auto-start with Windows, so it behaves like a background service rather than an application someone has to remember to open.
Are writes from a BMS or PLC safe?+
Yes. Writes forwarded to a BACnet device use the standard 16-level priority array (default priority 8, Manual Operator) instead of a blind overwrite, so they interact correctly with schedules and other controllers already writing to the same point. See our Priority Array guide for how this works.
Can I bridge multiple Modbus devices and multiple BACnet objects at once?+
Yes. The Gateway maps as many source points as needed — Modbus TCP, Modbus RTU, and already-discovered BACnet devices — into either a shared Modbus map or a BACnet server device, row by row.
Does this cost extra on top of the BACManager license?+
No. The Gateway is included in the standard $149 one-time BACManager license — no separate module fee.
