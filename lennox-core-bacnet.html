// before you start

Built in, set up from a phone

🔌

No BACnet module

The CORE Unit Controller has BACnet MS/TP and BACnet/IP on board. The Lennox BACnet modules people search for belong to older controls: 59W51 for Prodigy M2/M3, 38B35 for CORE LITE.

📱

Network Setup Wizard

In the CORE Service app: RTU Menu → Network Integration → Network Setup Wizard. Choose BACnet MS/TP or BACnet IP, the address, the control mode and the backup mode.

🌡

Room Sensor mode

Lennox recommends Room Sensor for BACnet: the unit controls to setpoints and occupancy sent over the network. Monitor Only ignores them; Network Thermostat takes heat/cool demands and is not recommended.

// the rule that bites

Write it again within five minutes

The CORE does not keep a BMS value for ever. Lennox's own time-outs:

5

Every 5 minutes

If they are used, these must be written again at least every 5 minutes: the network setpoints (AO:109, AV:130–133), occupancy (AO:104), space temperature, humidity and CO2 inputs, and network thermostat demands (AO:101). Lennox recommends every 2 minutes, so a lost write can be retried in time.

15

Every 15 minutes

The device as a whole must be written to at least every 15 minutes, or the CORE considers the network offline.

93

Then: backup mode

The unit drops to the backup mode chosen in the wizard — usually Return Air, with its own backup setpoints — and reports code 93. A CORE also forgets every BACnet command at a reset, so they must be sent again after one.

A BMS handles this with a periodic write. In BACManager a BACnet tag has Refresh (s): the last value written to it is written again every that many seconds until it is relinquished. The free workspace sets 120 s on the occupied setpoints and the occupancy. Tested against the simulated CORE with its time-out shortened to 30 s: with Refresh the unit stayed in Room Sensor mode for the whole run; without it, it was in backup mode within half a minute of the last write.

// writing to the unit

Three more things about writes

⏻

Off means off

Application mode 6 (Off) is a complete unit disable: outputs and timers are cleared. Don't use it to end heating or cooling as part of normal control — let the setpoints and occupancy do that.

⇄

Last setpoint wins

AO:109 (one setpoint, with AO:110 as offset) and AV:130–133 (four setpoints) both set the space setpoints; the CORE uses whichever was written last. Pick one style and stay with it.

🔧

A local tool overrides

When a service tool on the unit writes the same setpoint, the AO's status shows it as overridden. Check before assuming the BMS value is the one in force — AI:252 says what is.

Lennox CORE BACnet — FAQ

Where is the Lennox CORE BACnet points list?+
In Lennox's CORE Unit Controller BACnet Setup Guide, 508112-02, on lennox.com, sections 7 and 9. The table on this page lists the points a BMS uses most.
Do I need a Lennox BACnet module for a CORE unit?+
No. BACnet MS/TP and BACnet/IP are built into the CORE Unit Controller. The modules 59W51 and 38B35 are for Prodigy M2/M3 and CORE LITE controls.
Why does my Lennox unit go into backup mode?+
Because the network setpoints, occupancy or sensor inputs were not written again within 5 minutes, or nothing was written to the device for 15 minutes. Write them every 2 minutes, as Lennox recommends; the unit reports code 93 while in backup.
What are the CORE's default BACnet settings?+
MS/TP at 38.4 kbps with Max Master 127 and Max Info Frames 1; the device instance follows the MAC address, or on BACnet/IP the last octet of the IP address. BACnet/IP uses UDP 47808, which cannot be changed.
Which control mode should I use for BACnet?+
Room Sensor, which Lennox recommends: the unit controls the space to setpoints and occupancy written over BACnet. Monitor Only ignores them, and Network Thermostat mode is not recommended.
Does the Lennox CORE support COV?+
Lennox's guide says both: COV is not supported at the interface, yet its object tables mark it available on newer firmware. Poll the unit rather than rely on COV.
