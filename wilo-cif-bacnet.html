// before you start

Two CIF-Modules for BACnet

🔌

MS/TP or IP

The CIF-Module BACnet MS/TP (2190367) for RS-485, and the CIF-Module Ethernet Multiprotocol (2211408), which does BACnet/IP or Modbus TCP. Both go into the pump. Wilo publishes EDE lists for Stratos MAXO, Stratos GIGA2.0, Yonos GIGA2.0, Helix2.0-VE, Medana CH3-LE, SiFresh and Isar MODH1-E.

⚙

Pump firmware first

The pump needs a minimum software: a Stratos MAXO 01002500 for the MS/TP module and 01042500 for the Ethernet module (updated with the Wilo-Assistant app). On a twin pump the module goes in the main pump, and only the system's data is on BACnet.

📋

Not the same BACnet

The MS/TP module (PICS revision 4) has no ReadPropertyMultiple, no COV and no segmentation: B-SA and B-SS, ReadProperty and WriteProperty only. The Ethernet module (revision 16) is a B-ASC with ReadPropertyMultiple, WritePropertyMultiple and COV.

// control

A value reaches the pump only when it changes

⇄

Last write wins

The pump can be set from the BMS, its own button and display, or a remote: the last change wins. So the module passes a value on only when it changes. Writing the same setpoint again does nothing — if someone changed it at the pump, the BMS's unchanged value will not undo it.

✓

Forcing a value

Wilo's recipe: read the value the pump uses, write that back, then write the one you want — or simply another value and then the wanted one. It also warns about gateways that write on a timer: repeating a value is not the way to hold it.

1→7

Wilo's order

Parameter set (MO34) norm; bus command timer (MO1) OFF or MANUAL; control function (MO0); setpoint source (MO3) IF-Module; setpoint (AO0); the overrides (BO1–BO3) inactive; then pump on (BO0). Check each on its input twin: MI2034, MI2, MI0, MI3, AI34, BI0.

The outputs are commandable, but some have a floating default: Wilo realises it as a write at priority 16, so after every slot of the priority array is relinquished the Present_Value is not the Relinquish_Default. Inside the pump the commands rank: the external off input, then override off, override max, override min, override on.

// the rule that bites

The bus command timer wants SET again

🔒

Who may operate the pump

MO1 busCmd.TimerInp,Act decides. MANUAL: the pump's own menu and the BMS both, last write wins. SET: the BMS locks the local menu for the bus command timer, AO8 — 300 s, at least 20 s. OFF: the timer is off and the local menu stays locked.

⏳

Before it runs out

SET has to be written again within the timeout — Wilo's words are to repeat writing SET. If the BMS stops, the timer runs out (MI2 RESET): the pump can be operated locally, writes over the interface are blocked, and the pump shows an error. With SET_PRESET instead of SET it also loads fallback values (AO100, BO100, MO100/101).

?

Factory state

Wilo's text says the module locks the local menu and input IN2 from the factory, which is the OFF state; its EDE list gives MANUAL as the default value. Read MI2 to see which yours is in. The activation is stored and survives a power cycle.

In BACManager a BACnet tag has Refresh (s): the last value written to it is written again every that many seconds until it is relinquished. The free workspace sets 60 s on MO1 only — well inside the 300-second timer — and on nothing else, since the pump ignores a repeated setpoint anyway. Tested against the simulated Stratos MAXO with a 30-second timeout and SET written once: with Refresh the timer stayed ACTIVE for the whole 90-second run; without it, it went to RESET after 30 s and stayed there. MS/TP module without ReadPropertyMultiple: BACManager notices the refusal and reads it one property at a time by itself.

The Stratos MAXO workspace

One dashboard page for a Stratos MAXO on a chilled-water circuit: bus command timer state and time left, who operates the pump, pressure, flow, speed, duty point, power and energy, control function, warning and error — with the timer's SET written again every 60 seconds and the duty point set once.

1

Discover the pump

On the BACnet tab open MS/TP on the PC's RS-485 port at the pump's baud rate, or BACnet/IP for the Ethernet module, and press Discover. A pump with a MAC of 128 or more will not answer.

2

Open the workspace

Workspace → Open. The file reads device 4001; BACManager asks which discovered device takes its place and moves every point over.

3

Timer, then duty point

On the Dashboard press Run. Write SET (or MANUAL), the control function, the setpoint, then pump on. From then on SET is written again every 60 seconds. After BACManager restarts, write it once more.

Wilo CIF BACnet — FAQ

Where is the Wilo Stratos MAXO BACnet points list?+
In Wilo's EDE lists for the CIF-Module BACnet, one per pump family, and in the functional description of the CIF-Module. The table on this page lists the points a BMS uses most.
Which Wilo module do I need for BACnet/IP?+
The CIF-Module Ethernet Multiprotocol (2211408), which does BACnet/IP or Modbus TCP. For BACnet MS/TP it is the CIF-Module BACnet MS/TP (2190367).
Why doesn't my Wilo pump take the BACnet setpoint?+
Values are passed to the pump only when they change, and the last change from any source wins. Check also that the setpoint source (MO3) is IF-Module and the parameter set (MO34) is norm.
What is the Wilo bus command timer?+
MO1 busCmd.TimerInp,Act. Written SET it locks the pump's local operation for the timeout in AO8, 300 s by default; SET must be written again before that runs out, or the pump goes to local operation and blocks writes. MANUAL allows local and remote operation together.
Why can't my BMS find the Wilo pump on MS/TP?+
A MAC of 128 or more makes the module an MS/TP subordinate, which does not answer Who-Is. Use 0–127, the same baud rate as the trunk, and activate the module after the settings are made.
Does the Wilo CIF BACnet MS/TP module support ReadPropertyMultiple or COV?+
No. The MS/TP module serves ReadProperty and WriteProperty only. The Ethernet module for BACnet/IP adds ReadPropertyMultiple, WritePropertyMultiple and COV.
